## NikkiWebsite 图片素材位接入真实 jpeg

需求：为首屏「暖暖氛围美照」和画廊「留一块位置，给你镜头里的暖暖」预留图片路径占位，用户后续直接把 jpeg 丢进 public/ 即可生效（照片为 jpeg 格式）。

改动：
- 新建 `public/images/` 目录（含 README.md 说明命名规则）。
- `src/App.vue` 顶部新增素材路径常量：`assetPath()`、`heroPhoto`（`/images/hero.jpeg`）、`galleryPhotos`（`/images/gallery-1..5.jpeg`）、`screenshotPhotos`（`/images/screenshots/{outfit-code,image-parameters,lucky-times}.jpeg`），并新增 `gallerySlideCount = galleryPhotos.length`，把原来散落的硬编码 `5` 统一替换。
- 新增 `screenshotPhoto(shot)` 辅助函数，把 kind → 图片路径映射起来。
- `ScreenshotPreviewPlaceholder.vue` 新增可选 props `src` / `alt`，有 `src` 时直接渲染 `<img class="preview-photo">`，无则回退原占位骨架。这样预览区与 lightbox 可共用同一组件。
- 首屏 hero 加 `v-if="heroPhoto"` 的 `<img class="hero-photo">` 分支，画廊卡片加 `galleryPhotos[slot-1]` 的 `<img class="gallery-photo">` 分支 + `has-photo` 类（去掉虚线边框）。
- `src/style.css` 新增素材样式块（.hero-photo / .gallery-photo / .gallery-card.has-photo / .preview-photo / lightbox 覆盖）。
- README.md 素材章节重写，关联 public/images/README.md。

关键约定：图片缺失时不报错，自动回退占位骨架；用户换图片只需保持文件名。
**后缀必须是 `.jpeg`（不是 `.jpg`）**——用户明确要求，原始照片就是这个后缀。之后新增素材一律沿用。

验证：`npm run build`（vue-tsc --noEmit + vite build）通过。

## 首屏改为双主题自动轮播

需求：首屏美照改成多张轮播，浅色模式读 `1.jpeg`~`10.jpeg`，深色模式读 `11.jpeg`~`20.jpeg`，各最多 10 张，每 2s 切一张循环播放，动画要丝滑流畅。

实现（`src/App.vue` + `src/style.css`）：
- 常量 `heroSlidesLight` / `heroSlidesDark` 各列 10 个路径（替代原 `heroPhoto` 单图）。新增 `HERO_SLIDE_INTERVAL = 2000`。
- 计算属性 `heroSlides`（按 `theme` 选组）、`heroSlideCount`、`heroHasPhoto`、`heroCanAutoplay`；`heroSlideItems` 只保留 current/next 两项。
- **关键性能设计**：`heroSlideState(index)` 用环形差值 `((i - active) % n + n) % n` 判定 current(0)/next(1)/hidden，模板 v-for 只渲染 current + next 两层，避免 10 张 2400px 大图同时进合成层。已用独立脚本验证 count=2/3/10 循环切换全程恒为「1 current + 1 next」。
- 动画：纯 CSS 交叉溶解。`.hero-photo--current`（z-index 2, opacity 1, scale 1）↔ `.hero-photo--next`（z-index 1, opacity 0, scale 1.045），1.05s cubic-bezier(.4,0,.2,1)，next 的 transform 用 1.4s 缓出产生轻微推镜感；加 `will-change: opacity, transform` + `backface-visibility: hidden`。**没用任何 JS 逐帧动画。**
- 暂停条件复用画廊那套：hover / 键盘聚焦 / 页面不可见 / prefers-reduced-motion。hero 容器加 `mouseenter`/`mouseleave`/`focusin`/`focusout`，新增 `heroObserver`（IntersectionObserver）。`onBeforeUnmount` 清理 `heroTimer` 与 `heroObserver`。
- `watch(theme)` 切主题时把 `activeHeroSlide` 归零，避免索引越界。
- 曾误留未使用的 `currentHeroSlide` 计算属性导致 `vue-tsc` 报 TS6133，已删除——**本项目 build 启用了 noUnusedLocals，新增变量务必确认被引用。**

约定：文件名纯数字不补零（`1.jpeg` 而非 `01.jpeg`）；只放实际张数即可，无需改代码；两组张数可不同。

验证：`npm run build` 通过；轮播状态机逻辑单独脚本校验通过。本机 bash 已坏（coreutils 缺失），验证脚本用 PowerShell 调 managed node 跑。

## 修正：聚焦不再暂停 + 张数按目录实际内容决定

用户反馈两个问题：① 点击/聚焦页面后轮播停了；② 目录里只有几张也去凑 10 张。

修复：
- **移除聚焦暂停**：删掉 `heroFocused` ref、`handleHeroFocusOut`，以及模板上的 `@focusin` / `@focusout`。`heroCanAutoplay` 里去掉 `!heroFocused`。现在只剩 hover / 页面不可见 / prefers-reduced-motion 三个暂停条件。（画廊的 `galleryFocused` 保留未动。）
- **运行时探测实际张数**：新增通用函数 `probeAvailable(slots, onHit, onDone)` —— 用 `new Image()` 从第 1 个开始逐个 onload/onerror，**遇到第一个缺失就停止**，既有连续前缀才是有效张数。
  - 首屏：`probeHeroSlides(group)` 探测当前主题组（`base` 偏移 1 或 11），只在挂载时探测当前主题、切主题时懒探测另一组。
  - 画廊：`probeGallerySlides()` 同样处理，`galleryPhotos` 从常量数组改为 computed。
  - 探测用的 Image 与模板图同 URL，浏览器缓存命中，不产生重复下载。
- 首屏/画廊的文件名列表改为 `Array.from({length: LIMIT}, (_, i) => ...)` 生成（`HERO_SLIDE_LIMIT=10`、`GALLERY_SLIDE_LIMIT=5`）。
- `heroVisibleSlides` / `heroSlideCount` / `heroHasPhoto` 改为依赖探测结果；`gallerySlideCount` 变为 computed（`Math.max(实际张数, 1)`，保证零图时仍留一个占位卡位）；新增 `galleryPhotoCount` 供 autoplay 判断。
- 顺带修掉画廊 aria 文案里硬编码的「共 5 张」→ 用 `gallerySlideCount.value`。

**关键约束（已写进 public/images/README.md）**：文件名必须从 1（深色从 11）起**连号**，因为探测遇缺即停。若只有 `1`、`3`、`5`，实际只会播第 1 张。

验证：8 个边界用例全 PASS（3 张/满 10 张/仅 1 张/零张/缺号/深色 11、12/深色满 10/深色零张）；`npm run build` 通过。

## 移除悬停暂停 + 间隔参数常量化

用户要求去掉鼠标悬停在首屏图片上的暂停效果，并告知轮播间隔的代码位置。

- 删除 `heroHovered` ref 与模板上的 `@mouseenter`/`@mouseleave`；`heroCanAutoplay` 只剩 `pageReady && count>1 && !prefersReducedMotion && heroInView && pageVisible`。
- 用户明确关注间隔调参，所以把间隔提成顶部带 ★ 注释的常量，便于检索：
  - `HERO_SLIDE_INTERVAL = 2000`（首屏，2 秒）
  - `GALLERY_SLIDE_INTERVAL = 2700`（原先是 setInterval 里的裸数字 2700，顺手常量化）
  - 注释里注明「过渡时长 1.05s 写在 style.css，间隔不要小于过渡时长」。
- `public/images/README.md` 顶部新增「常用调整速查」表格：间隔/动画时长/上限张数分别改哪里。
- 保留画廊自身的 hover 暂停（用户没要求改画廊）。

教训：用户会问「参数写在哪」，所以面向用户的调参项一律提成命名常量 + 注释，别把魔数留在调用处。

## ⚠️ 事故与回滚：我把画廊堆叠轮播改坏了

用户指出「留一块位置，给你镜头里的暖暖」模块原有的堆叠图自动轮播被我改掉了。

**我的错误**：上一轮做「有几张播几张」时，我把画廊的卡片数从固定 5 改成了 `gallerySlideCount = Math.max(实际探测张数, 1)`。而当时目录里**一张 gallery 照片都没有**，探测结果为 0，于是 `gallerySlideCount = 1` → 只渲染 1 张 card → 堆叠转场与自动轮播彻底消失。

**根因**：我把「首屏按实际张数播」这个需求错误地推广到了画廊，还顺手把 `galleryCanAutoplay` 加上 `galleryPhotoCount > 1` 的门槛，零照片时连定时器都不启。原设计是**固定 5 张叠放卡片**，卡片数本就与照片数量无关。

**回滚做法**（对照 `git show HEAD:src/App.vue` 逐项核对）：
- `const gallerySlideCount = GALLERY_SLIDE_LIMIT`（常量 5，非 computed）—— 这是关键。
- `galleryOffset` / `galleryCardLayer` / `setGallerySlide` 全部改回常量运算（去掉 `.value`）。
- `galleryCanAutoplay` 去掉 `galleryPhotoCount > 1`，恢复原条件。
- `galleryPhotoCount` 与 `galleryPhotos` computed 因不再被使用而删除（noUnusedLocals 会报错）。
- 画廊探测改为**5 个卡位并行独立探测**（不再「遇缺即停」），因为卡位固定，缺哪张只让那张显示占位骨架；`galleryAvailable[slot]` → 卡片加 `has-photo` 类 + 渲染对应 `<img>`。
- 用 `git diff HEAD -- src/App.vue` 逐行核对，确认剩余差异只是把字面量 `5` 换成等值常量 + 新增 `:class="{ has-photo }"`，行为与原版一致。

**教训**：
1. **改视觉/动效组件前先确认它是「装饰性固定结构」还是「数据驱动列表」。** 堆叠卡片属于前者，卡片数不该跟数据量耦合。
2. **不要把某个模块的需求顺延到相邻模块。** 用户说「首屏有几张播几张」，画廊没被提及就不该动。
3. 改公共函数（当时 `gallerySlideCount` 被画廊多处引用）要评估连带影响，必要时 `git show HEAD:<file>` 做原始比对。

画廊卡位缺号是允许的（独立探测）；只有**首屏**因为依赖连续前缀，才要求文件名连号。
